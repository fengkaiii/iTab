## 多浏览器共享数据（指定文件存放）

### 当前数据存放位置
- 默认写入 `chrome.storage.local`（键 `itab.v1`），物理位置：`<Profile>/Local Extension Settings/<扩展ID>/`，LevelDB 二进制格式。
- 各浏览器、每个扩展 ID 各自独立，无法跨浏览器直接共用。
- Chrome：`~/Library/Application Support/Google/Chrome/Default/Local Extension Settings/<ext-id>/`。
- Edge / Brave 同理，路径不同；iTab 在 Chrome 与 Edge 的扩展 ID 相同（`pdkihkjkejccngnfcidmilkpbimbbnia`），但 storage 仍各 Profile 独立。

### 实现方案：File System Access API + 手动按钮触发
**为什么不用自动同步 / 目录句柄持久化：**
- macOS 扩展上下文下 `showDirectoryPicker` 存在已知 bug：popup/sidepanel 选中某些目录会报「system files」/「user aborted」错误甚至崩溃 Chrome（参考 badlogic/chrome-extension-fs-crasher）。新 tab 虽是全页也尽量避免目录选择。
- 浏览器重启后 File System Access API 权限不持久（state 回到 'prompt'），无法静默自动读写，需用户手势重新授权。

**落地做法：手动按钮触发的「共享文件」读写 + 句柄持久化到 IndexedDB。**
- 新模块 `js/filestore.js`：封装 `showOpenFilePicker`（单文件，比目录更稳）+ IndexedDB 句柄存储 + `requestPermission` 升级权限。
- API：`isSupported / pick / get / load / save / clear / friendly`。
- 写入用 `handle.createWritable()` 覆盖式写回，实现「同一文件 in-place overwrite」（突破传统 `a.download` 只能下载新文件的限制）。

### 注意事项
- 句柄按浏览器各自保存在各浏览器 IndexedDB，跨浏览器需各自「选择共享文件」一次。
- 不支持该 API 时（部分 Brave / Firefox）：`isSupported()` 返回 false，状态行显示「不支持」并提示改用导入/导出 JSON 兜底。
- 「保存到文件」需 `requestPermission({mode:'readwrite'})`，首次会弹授权提示（在按钮点击手势内，符合规范）。

### [hidden] CSS 失效全局修复（18:06）
- 反馈：用户截图显示便签与启动台仍同时出现（"样式和交互都有问题"）。
- 根因：作者样式的 `display` 优先级高于 UA 的 `[hidden]{display:none}`，导致 `element.hidden = true` 在 `.topbar{display:grid}` / `.stage{display:flex}` 等元素上**失效**。之前 `.btn[hidden]` / `.modal[hidden]` 等都是单独加高特异性规则补丁。
- 修复：在 launchpad.css 顶部加全局兜底 `[hidden] { display: none !important; }`，让所有 hidden 元素统一正确隐藏。
- 历史补丁：行 164 `.search-engine-menu[hidden]`、213 `.search-clear[hidden]`、497 `.modal[hidden]`、587 `.btn[hidden]`、707 `.icon-tab-panel[hidden]`——现在都被全局规则覆盖，行为一致。
- 提醒用户：Chrome 扩展需要去 `chrome://extensions` 点"刷新"按钮重新加载本地文件，才能看到本次及之前的全屏便签改动。

### 便签网格改瀑布流（18:14）
- 反馈：grid 布局下 `align-items: stretch` 让同一行便签高度被最长那条拉高，其他便签被拉伸 → 改**瀑布流**，每条便签高度由内容自然决定，保留 `min-height: 140px`。
- 改动：`.notes-grid` 从 `display:grid + grid-template-columns:repeat(auto-fill, minmax(200px,1fr)) + gap` 改为 **`columns: 220px; column-gap: 16px;`**（CSS multi-column 瀑布流）。
- `.note-card` 加 `break-inside: avoid; margin-bottom: 16px;`（避免便签被分到两列，列内垂直间距 16px）。
- `.notes-empty` 去掉残留的 `grid-column: 1 / -1`，改用 **`column-span: all`** 横跨所有列居中显示（瀑布流空状态标准做法）。
- 注意：multi-column 是列优先填充（先填满第一列再第二列），与 grid 的行优先不同；这是瀑布流的标准行为。
- 浏览器支持：columns/break-inside/column-span 均为 W3C 标准，Chrome/Firefox/Safari 桌面端均原生支持，无需 JS masonry。
