# 2026-09-08

## 给 iTab 增加分组模式

需求：分组模式开关 + 添加收藏时可填分组 + 开启后按分组归类显示。

### 数据层
- `item.group: string`（空字符串 = 未分组）
- `settings.groupMode: boolean`
- `migrate` 通过 `DEFAULT_SETTINGS` 遍历填默认值，老数据自动加 `groupMode:false`，`item.group` 由 `_normalize` 补空串
- 默认站点中 4 项归「开发」、2 项归「AI」、4 项归「中文」，其余归「未分组」——首次开启分组模式立刻能看到效果

### UI
- 添加/编辑弹窗新增「分组」字段 + `<datalist id="groupOptions">`，每次打开弹窗由 `_updateGroupDatalist()` 从所有 item.group 去重排序后填入
- 设置面板「布局」section 新增 checkbox `#fGroupMode`
- 分组模式开关的 change 监听：写 settings → 持久化 → render → toast 提示

### 渲染
- `Launchpad.render()` 入口判断 `state.settings.groupMode`：true 走 `_renderGrouped()` 返回；false 走原分页逻辑
- `_groupItems(items)`：用 Map 保序聚合，分组内顺序 = items 中相对顺序；空 group 项归到 `{ header: "" }` 放最后
- `_renderGrouped()`：每个分组一个 `<section class="group-section">`：
  - `.group-header`：分组名 + 计数胶囊 + 始终可见的 `+` 按钮（点击预填该组名）
  - `.group-grid`：flex-wrap 流式布局，每组末尾的 add-slot 仅在编辑模式显示
- 搜索过滤 `_applyFilter` 改为遍历全局 `.tile`，分组模式下隐藏没有可见项的 `.group-section`

### CSS
- `body.group-mode .stage` 改为 `align-items:flex-start; overflow-y:auto`（垂直滚动）
- `.group-section` / `.group-header` / `.group-name` / `.group-count` / `.group-add` / `.group-grid`
- 分组模式无分页器、`.page-viewport` 改 block

### 取舍
- **分组模式下禁用拖拽**：避免跨组语义混乱（拖到 A 组前的图标移动是全局 items 顺序变化，但渲染按 group 重新聚合，跨组拖拽不生效）。编辑模式的删除/编辑按钮照常。
- **滚轮/ArrowLeft/Right 翻页**：分组模式不拦截，让浏览器自然滚动分组容器。
- **每组末尾 add-slot**：跟随原有规则只在编辑模式显示（非编辑模式靠 header 的 `+` 按钮）。

### 调试参数
- `?group=1` 临时开启分组模式
- `?fresh=1` 把 items 重置为 DEFAULT_ITEMS（含分组），用于截图演示

### 验证
- chrome headless `--dump-dom` 验证：4 个 `.group-name`（开发/AI/中文/未分组）计数正确，datalist 含 3 个 option，弹窗 fGroup 字段绑定 datalist，设置 fGroupMode checkbox 存在
- 3 张截图归档到 `img/previews/09~11`（分组主图、分组模式添加弹窗、分组模式设置面板）
- 关键 bug 修复：`_applyFilter` 之前用 `.page .tile` 选择器，分组模式下会失效；改为全局 `.tile` 并加了空分组隐藏
## 分组支持拖拽排序（右侧侧边栏）

需求：分组可排序，在界面右侧纵向列出分组拖拽排序。

### 方案选择
用户给了两个方案（右侧纵向列表 / 藏到设置里）。选**右侧侧边栏**（用户放第一位、交互更直观）。

### 实现
- 数据：`settings.groupOrder: string[]`（不含「未分组」，空 = 首次出现顺序）。migrate 自动补默认值 `[]`。
- `_groupItems` 改为：按 groupOrder 顺序输出 → 未在 order 中的分组按首次出现追加 → 未分组固定最后。
- `_renderGrouped` 结构改为 `.group-layout`（flex）= `.groups`（主体）+ `.group-sidebar`（右侧 sticky 列表）。
- `_buildGroupSidebar` / `_buildSidebarItem`：每个真实分组一个 draggable item（⠿ 手柄 + 名称），HTML5 dragstart/dragover/drop 重排，`drop-target` 高亮。
- `_reorderGroup(from, to)`：以当前展示顺序为基准 splice 移动，`dispatch("group-reordered")` → app.js 持久化 `settings.groupOrder`。
- 未分组不进侧边栏（固定最后，语义上是兜底分组）。

### CSS
`.group-sidebar` 半透明毛玻璃 sticky 卡片；`.group-sidebar-item` 可抓取、拖拽中 `opacity .35`、目标位 `drop-target` 蓝色高亮；`.gs-grip` 手柄。

### 验证
- `?order=中文,开发,AI` 调试参数（app.js 新增）：dump-dom 确认 sidebar 与主体分区顺序都从「开发/AI/中文」变为「中文/开发/AI」，未分组仍最后。
- 截图归档 `img/previews/12-group-sidebar.png`。

### 调试参数新增
- `?order=a,b,c` 临时指定分组顺序。

用户反馈"位置太显眼，淡化视觉效果，去除外边框和标题，贴着右侧中间"。

### 改动
- `_buildGroupSidebar` 删除 `group-sidebar-title`（"分组排序"）和 `group-sidebar-hint`（"拖动排序"）两个元素
- CSS：`.group-sidebar` 去掉 background/border/border-radius/padding/backdrop-filter（彻底透明），width 172→132px，sticky top:50% + translateY(-50%) 实现垂直居中
- `.group-layout` `align-items: center` 让 sidebar 相对主体垂直居中
- `.group-sidebar-item` 去掉背景边框，默认 `opacity:0.55` 淡化，加 text-shadow 在浅色背景下可读，hover/drop-target 时 opacity:1
- 拖拽手柄 ⠿ opacity:0.4 同样淡化

效果：侧边栏像浮在背景上的浅色文字，不再是抢眼的卡片。截图归档 `img/previews/12-group-sidebar.png`。

### 侧边栏继续靠右

### 顶栏分组 toggle 按钮
用户要求在设置按钮旁加个分组模式开关。顶栏 left 区添加 `#btnGroupToggle`（文件夹图标），点击调 `_toggleGroupMode()` 即时切换 groupMode 并 render + toast。新增 `_syncGroupToggle()` 同步按钮 `active` 类、`aria-pressed`、title 与设置面板 `#fGroupMode` checkbox 的状态。CSS `.icon-btn.active` 蓝色高亮背景。截图归档 `13-group-toggle-on.png` / `14-group-toggle-off.png`。

## 聚合搜索：放大镜图标切换搜索引擎

- `store.js` 新增 `ENGINES` 常量：google/bing/duckduckgo/baidu，各含 name/short/color/url(q) 工厂函数，导出到 `itabStore.ENGINES`。
- `launchpad.js` 搜索回车改用 `itabStore.ENGINES[searchEngine].url(q)`，去掉内联 engines 对象。

### 验证
- dump-dom 确认 4 个 se-item（Google/Bing/DuckDuckGo/百度），默认 active=google；`?se=1` 时 menu 无 hidden 属性（展开）。

## 修复：中文输入法回车确认候选词误触发搜索

现象：中文输入时输入法有候选词，按回车确认上屏，结果触发了网页搜索。

根因：搜索框 keydown 监听里，Enter 一律 `preventDefault()` 并搜索，没区分「输入法组合中确认候选词」和「普通回车提交」。

修复（launchpad.js 搜索框绑定处）：
- 新增 composition 跟踪：`compositionstart` → composing=true，`compositionend` → composing=false
- keydown 里计算 `isComposing = composing || e.isComposing || e.keyCode === 229`（三重保险，229 覆盖 Safari 等 keyCode 场景）
- Enter / Escape 若 isComposing 则直接 `return` 且**不 preventDefault**，让输入法正常上屏/取消候选

这是 IME composition 的通用处理范式。`node --check` 三文件语法通过。
